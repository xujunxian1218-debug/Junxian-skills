# 流程图指南（5 形态判别与图式要求）

> 第 4 段「法」画图前先读本文件。核心原则：**形态判别先于画图**——不同流程形态的图式不可互换，用错形态的图比不画图更误导。

## 六要素（每张图必须齐全）

前置条件、决策节点、分支路径（有分支必须画）、回退机制、质量检查点、结束条件。

图后必须附「流程要素对照表」，逐要素对照说明。

## 5 形态判别表

| 形态 | 判别特征 | 图式要求 |
|---|---|---|
| **1. 循环型** | 非确定次数的循环对话，或 session 级持久化规则 | 自循环箭头 + 标注循环退出条件。两个子类：**循环体各异**（逐个澄清直到完成，退出条件 = 所有问题已澄清）/ **循环体相同**（同一套规则反复应用于每轮响应，退出条件 = 用户主动终止或 session 结束）。**不要用线性展开伪装循环** |
| **2. 多模式型** | Skill 含多种工作模式 | 按模式数量分级：**≤6 种**以最核心模式为主流程完整展开，其他模式以分支入口标注差异点；**>10 种**以「模式族」为单位呈现，完整模式-结构-纪律对照放「术」段决策表。各模式差异在流程要素对照表中单独列出 |
| **3. 状态机型** | gate 有严格顺序约束、session 有冷启动 / 续接规则、已完成 gate 不可覆盖 | 完整画出状态转换路径 + 独立决策表呈现「前置条件 + session 要求 + 可覆盖性」三列约束。**不要用普通分支流程图伪装状态机** |
| **4. 嵌套子流程型** | 某分支调用 references 中的独立流程文档 | 主图中以子流程节点标注入口条件和退出条件，不展开内部细节（子流程内容在「术」段完整呈现） |
| **5. 产物机器检查型** | 含机器可执行的产物检查脚本，结果分硬禁令 failures（阻断）与形状 warnings（人工判断） | 完整画出机器检查 gate 及三态结果分支（failures 回修 / warnings 人工判断 / clean 通过），「术」段用决策表呈现检查项分类。与状态机型的区别：本类是单次产物规则扫描，无顺序 / session / 不可覆盖约束 |

## 两条伪装警告

判别错误最常见的两种「伪装」，终检时对照自查：

1. **线性伪装循环**：把逐轮澄清 / 每轮生效的规则画成一条直线加几个节点——丢了「退出条件」这个最关键的信息
2. **分支伪装状态机**：把有顺序约束、不可回退、session 续接规则的 gate 画成普通 if/else——丢了「状态不可覆盖」的约束信息

## 无显式流程的 Skill

纯协议型 Skill（只约束表达 / 认知，无流程步骤）没有业务流程可画。此时画**认知流程**：规则如何在每轮对话中生效（输入 → 规则匹配 → 输出约束 → 例外分支），并在图前标注「本图为分析者推导的认知流程，非原文显式流程」。

## 渲染兜底

分析卡是 Markdown 文档，Mermaid 以源码形式保留即可——支持渲染的阅读器直接渲染，不支持的读者仍可读图后的流程要素对照表。不要因为渲染环境不确定而改用纯文字描述流程结构。
