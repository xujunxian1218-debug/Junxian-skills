# 条件触发总表（条件字段 + 条件角度）

> skill-teardown 的条件项判定速查。第 2 步判别时通读本表，第 3 步产出时按命中项展开。
> 设计原则：**条件触发优先于默认必填**——没命中就不写，命中才展开。判别结论（命中与否）记录在卡内。

## A. 元信息条件字段（3 项）

| 字段 | 触发条件 | 要写什么 |
|---|---|---|
| **分发形态** | Skill 有构建产物或多分发通道（skill 目录 / 单文件 prompt / 双形态） | 分发形态；**仅以构建产物存在且未接入入口 / 构建管线 / 安装脚本时，必须显式标注断链**——构建产物再好，用户摸不到入口就等于不存在 |
| **变体关系** | 仓库通过多分支提供同一 Skill 的变体 | 变体关系 + 差异验证方式 + 移植删减项。多变体各自立卡，互为对照 |
| **所属生态** | Skill 硬编码引用生态共享设施（其他 Skill 路径 / 共享脚本 / 门禁规则文件 / 目录约定 / 子代理定义），**或被其他编排型 Skill 硬编码调用** | 生态归属 + 共享设施清单 + 单点维护项（改一处全生态生效的资产）。命中形态必须区分两种：**引用式生态（主动）**= 本 Skill 主动硬编码引用生态设施；**被编排生态（被动）**= 本 Skill 被编排方（pipeline 等）硬编码调用而自身可能不知情——被动命中时标注编排方名称与调用契约（输出路径 / 数量 / 框架等），契约漂移是被动形态的高发风险点，进第 7 段一致性类。**共享方式必须区分**：引用式 = 单点真相源；复制式 = 同文件多份副本——复制式必须在第 7 段一致性类标注漂移风险 |

## B. 第 8 段条件角度（8 项）

| 角度 | 触发条件 | 要写什么 |
|---|---|---|
| **自指型分析注意事项** | 被分析 Skill 与分析行为同类（分析 Skill 的 Skill） | 标注方法论异同，避免用自己的标准天然偏袒或贬低同类设计 |
| **面向终端用户的术语隐藏设计** | Skill 面向非技术终端用户 | 对用户说人话、对系统做结构化维护的双层设计（「对用户说人话，对系统做结构化维护」） |
| **词汇控制纪律** | Skill 对术语使用有显式约束 | 术语表来源 / 禁用替代表 / 约束深度（仅内容 vs 连收益描述都约束）/ 是否有机器校验。与反偷懒角度的界定：偷懒纠正聚焦行为，词汇控制聚焦术语精确性 |
| **完成 / 过程产物区分** | ≥5 步流水线且显式区分 checkpoint | 如何区分过程产物与最终交付物、如何防止「停在中间交半成品」 |
| **运行时能力探测** | Skill 显式探测运行时环境能力 | 探测对象 / 探测方法（实际遍历 vs 凭记忆）/ 强制证据门槛 / 跨平台适配。与外部依赖链的界定：依赖链是静态文件清单，能力探测是运行时动态发现。**命中判别正反例**：✅ 正例——探测「某脚本/命令/浏览器是否可用」（如三级探测降级表、执行前 which/版本探测）；❌ 反例——Step 0 的 Glob/文件扫描发现已有文档属**静态文档发现**，不构成环境能力探测；边界情形（探测目标恰是文件存在性且结果决定后续行为）可记边缘命中，但必须注明疑点 |
| **agent 间状态共享机制** | 多代理协作型 Skill | agent 间如何共享状态（项目记忆 / 文件交接 / 无）+ 共享层的治理边界 |
| **完成契约 / 终态判定** | Skill 显式区分过程 / 终态，或涉及破坏性动作 | 「收尾何时算完」的完成判定：完成契约（事实面 × 状态）/ 发布状态机（merged ≠ deployed ≠ verified，失败停格如实汇报）/ 清场确认门（完整汇报 + 用户明确确认 + 凭证，预授权不替代） |
| **记忆治理边界** | Skill 涉及 agent 记忆读写 | 三类文件区分（人工规则 / 自动记忆 / 生成索引）、写入授权边界（生成物只走官方控制面）、平台阈值绑定（不跨平台套用尺寸阈值） |

## 判别纪律

1. 逐项过表，**命中与否都记**——「检查过且未命中」与「没检查」是两回事
2. 触发条件的判断拿不准时，倾向写入并在该角度内标注「触发判断存疑 + 疑点」
3. 一个 Skill 命中多项是常态（如多代理协作型常同时命中状态共享 + 完成契约）
