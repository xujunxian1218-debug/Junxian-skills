For people who collect skills

它不告诉你好不好，只告诉你凭什么有效。

不用先懂分析框架。你只要记住一件事：skill-teardown 把任意一个 Agent Skill 拆成一张九段分析卡——道法术例戒，可学习、可复用、可溯源。

The problem

没有它时，读懂一个 Skill 靠脑补。

页面不先讲九段结构，而先讲读法的差别：为什么「看懂了」和「拆明白了」是两件事。

普通阅读式理解

用户：帮我看看这个 Skill 讲什么。
Agent：它是一个做 X 的工具，有 A、B、C 功能……
三天后：想不起来它为什么好用。
问题在哪里

摘要复述功能清单，没有知识增量；评分回答的是「好不好」，不是「凭什么」；更糟的是，原文观点和你自己的解读混在一起，分不清哪些是它说的、哪些是你猜的。

skill-teardown 式拆解

1
先判别类型与形态决定用哪类眼光看它
2

3

变化是什么

读法从「浏览」变成「拆判断」：为什么这样设计、哪些资产能搬走、什么时候会坏——全部显式化，并且逐条标注是原文明示、约束推导还是分析者补充。

Why it helps

它主要补上三种能力。

分得清、拿得走、躲得开——这三件事有了，看过的 Skill 才会变成你的知识。

分得清

溯源纪律：原文观点、约束推导、分析补充三态标注，关键处引用原文，观点可回链材料。

拿得走

术段资产：检查清单、决策表、关键话术、契约定义——每项都按「拿走就能用」的标准沉淀。

躲得开

戒段边界：适用边界、外部依赖链、一致性风险，三类各至少两条具体发现，引入前先看会怎么坏。

What the skill does

它只做一件事：产一张九段分析卡。

边界越清楚，越容易理解。摘要、评分、改造建议都刻意不做——那是别的工具的职责。

A. 五步拆解

从材料准入到终检，每步都过自己的门，终检不通过的卡不得标记为完成。

analysis-cards/{skill名}.md

一卡一 Skill，不覆盖旧卡

材料准入 定深度 通读三判别 逐段产出 终检
每步的门是什么

材料缺失先一次性通报、禁止把没读到伪装成读过；段落有硬上限，中检拦在段内；三档深度（快扫 / 标准 / 深度）按需选择，未明说时按标准执行并说明。

B. 三条边界

不写摘要、不打分、不改造——产出的是关于被拆对象的知识，不是对它的修改。

边界声明

先立住，再动笔

不写摘要 不打分 不改造
为什么要刻意设边界

复述功能清单没有知识增量，摘要工具能干的事不重复造；质量评分与改进建议是审计工具的职责；拆解只沉淀「它凭什么有效」的知识，风险只在戒段指出，不给修改清单。

Card map

点击左侧按钮，看每一段解决什么问题。默认只展示核心职责，细节藏在展开项里。

Quality gates

红线不是口号，是逐条可执行的门。

违反任何一条，卡不合格。这些门内置在流程里，不依赖你记得住。

它怎么拦

1溯源：所有「原文观点」必须能在输入材料中找到依据。
2推断标注：不确定的判断必须标注三态之一，不装确定。
3道段禁空话：「注重质量」类判失败，判断句必须能解释设计取舍。
4戒段下限：三类检查各至少两条具体发现，确无发现要说明为何。

怎么用它

纯提示词 Skill，零脚本零依赖，任何 Agent 都能跑。对 Agent 说一句话即可：

帮我拆解 ~/skills/xxx 这个 skill，出一张分析卡
三档深度怎么选

「看看 / 值不值」走快扫，回答值不值得深究；「拆解 / 分析卡」走标准，九段全产出；「深度 / 学方法论」走深度，含同类对照。所有质量门为 AI 自评纪律而非机器脚本——框架提供纪律，不提供保证。
